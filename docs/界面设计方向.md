# MingOff 界面设计方向（Pass 1 + Pass 2 自评）

> 目的：给老板看 demo 前的设计定调。避免 AI 默认审美，从**史料本身的物质形态**取材。

---

## 一、先钉死三件事

| 项 | 取值 |
|---|---|
| **具体主题** | 崇祯朝（1628–1644）中央职官的**按年在任**查询 |
| **受众** | 明史研究者、研究生、数字人文学习者 |
| **这一页唯一的任务** | 拖动年份 → 看清那一年谁在任、任期边界在哪、依据什么 |

核心交互是**年份**不是人物。所以页面主轴是时间，不是列表。

---

## 二、为什么不能用 AI 默认三套

frontend-design 明确点出 AI 设计扎堆的三种样子：

1. 暖米色背景 + 高对比衬线 + 陶土色点缀
2. 近黑背景 + 单一荧光绿/朱红
3. 报纸式细线大栏

**第 3 种离"史书"最近，也最危险**——遇到历史题材，AI 十有八九会做成一页仿古报纸。
所以我要**刻意避开"仿古书"路线**，理由如下：

- 《明史》七卿年表**本来就是表格**，不是竖排书页。做成竖排仿古是**主题错位**。
- 目标用户是研究者，他们要**快速比对**，不需要"沉浸式古籍氛围"。
- 年表的信息密度极高（一年 8 个职位），装饰性元素只会干扰阅读。

**我选的方向：以"年表"为原型，做现代学术工具，不做古风皮肤。**

---

## 三、设计令牌（Pass 1）

### 颜色：取自明代官方文书与朱墨套印

不用"米色+陶土"（AI 默认 1）。取**明人公文与套印本的实际用色**：

| 名 | 值 | 用途 | 依据 |
|---|---|---|---|
| 墨 | `#1B1A17` | 主文字 | 松烟墨，偏暖黑而非纯黑 |
| 宣 | `#FBFAF7` | 底 | 宣纸白，极淡暖调，**比 #F4F1EA 亮得多**（避开默认 1） |
| 靛 | `#1F3A5F` | 主强调、在任条 | 明代官服/公文常用靛青 |
| 朱 | `#A8322D` | 仅用于"缺载/存疑" | 朱笔批点——只用在小面积警示 |
| 灰 | `#6B6960` | 次要文字、网格线 | 中性偏暖 |

**关键约束：朱色只表示"不确定"，不表示强调。** 这是内容驱动的——本项目
的核心价值就是诚实标注不确定性（`confidence`/`discrepancy`），所以用**朱批**
这个真实存在的校勘动作来做视觉语义。这是这个设计唯一"有意义"的颜色用法。

### 字体：三级分工

避开 Inter/Roboto/Space Grotesk（AI 默认）。

| 角色 | 字体 | 理由 |
|---|---|---|
| **年号/大标题** | 思源宋体（Noto Serif SC） | 明代年表本就是宋体刻本的字形传统 |
| **正文/人名** | 思源黑体（Noto Sans SC） | 现代学术工具需要清晰无衬线 |
| **数据/年份/置信度** | JetBrains Mono 或 IBM Plex Mono | 数字要等宽才能对齐比对 |

三级都是**开源可自托管**的（项目要开源上线，不能依赖私有字体 CDN）。

### 布局：横向时间轴 + 纵向职位栏（更新：不要按下面布局来）

```
┌──────────────────────────────────────────────────────────┐
│  MingOff                          崇祯 元年 — 十七年       │
│  明代职官数据库                                            │
├──────────────────────────────────────────────────────────┤
│                                                            │
│   ◀ 1629 ▶        崇祯二年                                  │
│   ├──────┼──────┼──────┼──────┼──────┼──────┼──────┼──►   │
│   1628   1630   1632   1634   1636   1638   1640   1642    │
│                  ▲                                         │
│              当前年份（可拖）                                │
├──────────────────────────────────────────────────────────┤
│  内阁首辅   │ 周延儒  ██████░░░░░░                        │
│             │         (1628–1629)                          │
│  吏部尚書   │ 王永光  ████████░░░░░                        │
│  戶部尚書   │ 畢自嚴  ░░███████████░                       │
│  兵部尚書   │ 王洽    ░█████░░░░░                          │
│             │ 申用懋  ░░░░█░░░░░░░  署理 ← 朱色小标        │
└──────────────────────────────────────────────────────────┘
```

**要点**：
- 每年一条竖线贯穿所有职位栏，一眼看出"这一年谁在任"
- 任期用色条表示，**空心=署理，实心=实授，细线=加衔**（用形态而非颜色区分类型——
  颜色已经被"不确定性"占用了）
- 缺载年份留**空白**，不填补。空白本身就是信息（PRD 的核心原则）

### 签名元素：年份游标

页面唯一"被记住"的东西：**一根可拖动的竖直游标**，拖过时间轴时：
- 所有职位栏实时高亮该年的在任者
- 右上角显示该年的**年号纪年**（「崇祯二年」）与公元年并置
- 交接年份自动显示"双人重叠"的视觉提示

这一个元素承载了 PRD 的核心卖点（按年看职官），其余部分保持安静。

## 四、Pass 2 自评（按 skill 要求，动手前先批一遍）

| 检查项 | 结果 |
|---|---|
| 是否落进 AI 默认 1（米色+衬线+陶土）？ | ❌ 已避开：底色 `#FBFAF7` 更亮；强调色是靛青不是陶土；朱色只作"存疑"小面积用 |
| 是否落进 AI 默认 2（黑底+荧光）？ | ❌ 浅色底 |
| 是否落进 AI 默认 3（报纸细线大栏）？ | ⚠️ **擦边**——时间轴+细网格确实像报纸。但**内容本就是年表**，表格线是信息结构不是装饰，且主视觉是色条不是文字栏。**保留，但在细节上区分**：用色条厚度与圆角做成"档案标签"质感，而非细发丝线 |
| 字体是否用了默认？ | ❌ 已避开 Inter/Roboto/Space Grotesk，用宋/黑/等宽三级分工 |
| 结构装置是否编码真实信息？ | ✅ 竖游标=年份，色条=任期，空心/实心=任职性质，空白=缺载 |
| 是否有一个可辨识的签名元素？ | ✅ 年份游标 |
| 是否只在"不确定性"上用朱色？ | ✅ 朱色语义专一，不滥用 |

**改动记录**（自评后调整的）：
1. 原计划用「米色 `#F4F1EA` + 朱红强调」→ **改**：这正是 AI 默认 1。
   改为更亮的宣纸白 + 靛青主调 + 朱色仅作存疑标记。
2. 原计划做**竖排**职位名（仿古）→ **改**：目标是研究者的比对效率，
   竖排会拖慢扫描。改横排。
3. 原计划用颜色区分实授/署理/加衔 → **改**：颜色语义已分给"确定性"，
   改**用色条的形态**（实心/空心/细线）区分，避免一个通道承载两种语义。

## 五、技术选型（为开源上线考虑）

| 项 | 选择 | 理由 |
|---|---|---|
| 技术栈 | **单文件 HTML + 原生 JS**（demo 阶段） | 双击即看，不要求老板装环境；也便于快速迭代设计 |
| 正式版 | 待定（React/Vite 或 Astro） | demo 通过后再定 |
| 依赖 | 零（无 CDN、无框架） | 开源项目不该在 demo 阶段就背依赖；字体用系统回退 |
| 数据 | 内嵌 JSON | demo 自带数据，不依赖后端 |

> 字体在 demo 阶段用**系统已装的字体回退链**（宋体/黑体），不联网取字体——
> 避免"打开是空白等字体加载"的糟糕第一印象。正式版再自托管。

## 六、demo 的验收标准（给老板看什么）

- [ ] 拖动年份游标，8 个职位的在任者实时变化
- [ ] 年份显示「崇祯X年」与公元年并置
- [ ] 实授/署理/加衔**形态可区分**
- [ ] 缺载显示为空白，**不编造填充**
- [ ] 点某人可看其任期详情（起止、类型、离任原因、来源、置信度）
- [ ] 窄屏可用（至少不崩）
- [ ] 无网络也能打开（字体/数据全内嵌）

**明确不做**（避免 demo 变半成品）：地图、关系网络图、后台、登录、账号。
