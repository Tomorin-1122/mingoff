# 数据接入规范（MingOff v3）

> 目的：把「史料 → 结构化数据 → 站点」的每一步写成可验收的规则，
> 避免 2026-10-17 之前出现过的错误（丢无注文行、合并单元格只取一人、
> OCR 变体重复、CBDB 同名错挂、南明混入等）再次发生。
> 本规范对新增史料源、新增职位（阶段②+）一律适用。

---

## 0. 三条不可协商的原则

1. **可溯源**：每一条任职/人物/事件都必须能回答「依据哪本书、哪一卷/哪一页/哪条注文」。
   没有来源的记录不得入库。
2. **不臆造**：史料未载 = `NULL`。月份、年份、籍贯、生卒没有就空着；
   不得用 0、不得用「同年首位」等推断冒充数据（首辅、署理等尤其危险）。
3. **单一真源 + 校勘层**：主数据来自一个指定源；其他源（CBDB/明史/维基）
   只作为校勘/断言（discrepancy）或人物对齐，不悄悄混入主数据。

---

## 1. 来源分层与登记

| 层 | 例子 | 用途 | 是否入主数据 |
|---|---|---|---|
| L1 原书 | 张德信《明代职官年表》册1（PDF 扫描） | 最终裁决 | ✅ 主数据 |
| L2 OCR/抽取 | MinerU Markdown、人工转录 | 工作载体 | ✅ 但须按第 3 节校验 |
| L3 结构化库 | CBDB SQLite、中研院检索结果 | 人物对齐 / 校勘 | 仅 `cbdb_id`、人物小传、实录命中 |
| L4 二手整理 | 《明史》宰辅年表、维基列表、《明人传记资料索引》（校勘/出处） | 校勘/断言 | ❌ 不直接入主数据 |
| L5 商业/受限平台 | 引得、需要机构 IP 的平台 | 不使用 | ❌ |

**每个新来源必须登记**：书名/版本/出版信息、页码范围、抽取工具与日期、
许可条款、可复现命令。未登记来源不得进入 `src/mingoff/data/`。

> 《明人传记资料索引》（1965/1978 台湾中央图书馆编，中华书局 1987 影印）的
> 定位与用法见 [明人传记资料索引评估](明人传记资料索引评估.md)：只取**事实摘要 +
> 出处引用**，不整段搬运小传原文。

## 2. 文件与字段规范

### 2.1 源提取物 `vol1_entries.json`

```json
{"year": 1402, "person": "解縉", "note": "八月,侍讀；十一、戊子、九,遷侍讀學士。",
 "src": "table|text|book-patch", "raw_person": "解 繉"}
```

- `year`：公元年（int），必须落在该来源覆盖范围内；
- `person`：**已归一的正字**（见 3.2），不得留 OCR 异体；
- `note`：原文注文（保留标点/异体，不做白话改写）；无注文可为空串；
- `src`：`table`（表格）、`text`（Markdown 文本段）、`book-patch`（回原书页补录）；
- 唯一键：`(year, person)`。**归一后必须唯一**（见 3.4）。

### 2.2 任职段 `tenures[]`

| 字段 | 规则 |
|---|---|
| `start_year/end_year` | 必填；年内连续段 |
| `start_month/end_month` | 1–12 或 `null`；**绝不允许 0** |
| `month_conflict` | 同年入离且月倒挂时为 `true`，保留原值不交换 |
| `end_clamped` | 因 1644.3 断限截断时为 `true`，与史料月份区分 |
| `confidence` | 0.5–0.8；明确入职事件 + 明确离任事件 0.8，单边 0.7，多年在任无事件 0.6，单年无事件 0.5 |
| `leave` | 注文离任动词直译；无则 `未載` |
| `note` | 段首年原文注文（可含跨年引用，但跨年引用不参与当年月判定） |
| `years` | 该段在任年集合，必须连续 |

### 2.3 人物小传 `person_profiles.json`

只从 CBDB 搬运，不做推断：`birth/death`（年精度）、`native_place`（籍贯）、
`alt_names`（字/号/谥/别名）、`entry`（入仕）、`offices`（历任，最多 30 条 + 总数）、
`cbdb_id/cbdb_name`。生卒只有年时不得补月日。

### 2.4 实录命中 `shilu{}`

- 只收「命中公元年 ∈ 本人任期 ±1 年」的记录；
- 每条保留 `source`（实录名+卷次+年号纪年）与 `content` 原文；
- 每人最多展示 8 条，另记 `count`；不得把全文批量搬进自建库（D10）。

## 3. 文本抽取规范（最易出错，逐条执行）

> PDF → OCR 中间产物这一段（切片、页码校准、版式测绘、O1–O5 校验）见
> [年表PDF_OCR规范](年表PDF_OCR规范.md)；本节只管拿到 OCR 文本之后的结构化。

### 3.1 表格解析

1. **按 `<tr>/<td>` 逐格解析**，禁止按文本行"猜"人名与注文；
2. **无注文的人名行也必须入库**（旧版 `if cur_person and buf` 的教训）；
3. 展开 `colspan/rowspan`：`<td colspan=2>張 瑛 十、丙寅…` 要拆成「名 + 注」；
4. 多人同格（「嚴嵩徐階李本」）按人名表切分；切不动时按姓氏兜底并记录待校；
5. 年号头容错：拆成多格（嘉靖卅三年 / 甲寅 / 1554）、干支 OCR 变体、
   表格跨页断行；识别不到年份块必须列入缺块清单，回原书页补录；
6. 纯 Markdown 段与 HTML 表格段要统一处理（同一段可能两种格式混排）。

### 3.2 人名与实体

- 先按**正字表**（上一轮 443 人 + 新增）归一人名；
- OCR 变体（解繉→解縉、蕭鎐→蕭鎡、曹霸→曹鼐、朱廣→朱賡、林鈺→林釬…）
  必须进别名表并注明依据；
- 同名不同人不得合并；
- 合并同一人必须有至少两条独立证据（正字表/原书页/CBDB），合并后保留 `raw_person`；
- CBDB 对齐：优先精确同名 + 生卒/任期相容 + 有相关官职记录；
  CBDB 同名多 id 时取记录更完整者并记录理由；无可靠候选时 `cbdb_id = null`，
  **禁止用「同名里记录最多」硬挂**。

### 3.3 时间与精度

- 年表体例：某年列名 = 该年在任；不得把「无事件年」当成离任；
- 起月：注文中明确入职事件（入/任/起/召/入直/入閣…）的月；
  无入职事件时退回本年纪月，但**降置信度**，不得冒充精确；
- 跨年引用（“正統元年十、…卒”写在 1429 年注文里）属于后年事件，不参与当年判定；
- 闰月：记入同名平月 + `leap` 标记，不另设格；
- 断限：1644 年三月后的任命一律剔除；末任截到 1644.3 并打 `end_clamped`。

### 3.4 去重

- 条目层：`(year, person)` 归一后必须唯一（实测 1402 解縉、1441 曹鼐 重复）；
- 段层：同年同人重复会导致两条重叠色块，构建时必须防御性去重；
- 人物层：同一 CBDB person 只允许一个主正字；别名放 `raw_person`/`alt_names`。

### 3.5 年份归属（OCR 年份头错位，2026-10-18 新增）

表内「年份头」可能被 OCR 挪位：出现在上一年末行的末尾、下一行开头、或与人名同格。
**不能只按「年份头所在行」归属人名**，按以下顺序判定（详见年表PDF_OCR规范 5.2.1）：

1. 年份头前有注文、后有人名 → 人名+注文归**上一年**（实测 1441 曹鼐、1572 殷士儋、1584 許國）；
2. 一格多名（无注文整名单）→ 归**本年**（实测 1417/1458/1488/1518）；
3. 单人名 + 纯年份头：若同年后文再出现同名 → 归**上一年**（实测 1616 吳道南）；否则归**本年**（实测 1618 方從哲）；
4. 裸名行紧挨在年份头之前、且上一年已有该人的带注文行 → 该名归**下一年**（实测 1412 胡廣，按原书 p19 补录）；
5. 判定存疑时一律回原书页，不得用前后年插值。

## 4. 范围与断限（D15/D17）

- 画布：洪武元年（1368）— 崇祯十七年三月（1644.3）；
- 内阁数据：1402（建文四年）始设，之前留空，不补假数据；
- **南明不做**：1644 年三月后任命（高弘圖、王應熊 1644-08、史可法、馬士英、
  王鐸、姜曰廣等）剔除；三月前在任者保留并截到 1644.3；
- 皇帝行、年号 chip 的边界必须与画布一致。

## 5. 校验门（每次数据变更必跑）

| Gate | 检查 | 失败处理 |
|---|---|---|
| G1 解析 | 年份 1402–1644 无缺块；`(year,person)` 无重复；人名归一率 ≥99%；年份归属抽检（每人前后年名单与《明史》/殿阁表一致） | 回原书页补录/加别名，不得忽略 |
| G2 实体 | 每段 `years` 连续；无负宽段；CBDB 映射生卒/任期相容；NULL 者列入清单 | 修映射或留 NULL |
| G3 时间 | 月 ∈ 1–12 或 null；无倒挂（`month_conflict` 除外）；无 start > 1644.3 | 修解析/剔除 |
| G4 导出 | `pytest` 全过；`official.py` 数字与报告一致；站点无越线色块 | 不提交 |
| G5 人工抽检 | 随机 20 年 + 名人锚点（楊士奇/張居正/徐階/崇禎诸臣）对照原书 | 记录到报告 |

**自动化测试是硬门槛**：新增数据/职位必须同时补测试，至少覆盖：
年份覆盖、人-年唯一、月合法、无倒挂、断限剔除、CBDB 关键 id、导出 meta。

---

## 6. 变更流程

1. 改解析/对齐脚本 → 2. 重跑数据管线 → 3. 跑 G1–G4 + 抽检 → 4. 更新
`docs/正式数据管线报告.md` 数字与变更说明 → 5. 同一次提交包含：
脚本 + 数据资产（entries/mapping/official_cabinet/person_profiles）+ 测试 + 报告。
**禁止只改 JSON 不写来源与校验、禁止静默覆盖历史数据**。

## 7. 今天踩过的坑（逐条记住）

1. 年表**逐年列名**，但旧解析丢弃无注文行 → 360 段假碎片；
2. 合并单元格只取一人 → 張瑛整人丢失、注文挂错到楊溥；
3. 年号头拆格/干支误识 → 1554 整块识别失败、1515 整块 OCR 丢失；
4. 人名归一后重复 → 1402 解縉出现两次、1441 曹鼐重复；
5. CBDB 同名错挂 → 楊士奇 28113（实为另一条记录）、曹鼐 199155、方逢年 38925；
6. CBDB 内部本身有重复人物（楊士奇 28113/楊寓 66729），对齐时要看记录完整度并写明理由；
7. 旧数据/ demo 混合口径不可复用于正式数据（D21）；
8. 1644 年三月后的南明任命混入 → 1644 年人数虚高；
9. 「年表首位 = 首辅」未经验证不能自动推断（见第 8 节）；
10. 只做前端不做数据校验 → 错误数据被画得更好看；
11. 年份头被 OCR 并进上一年末行/下一行首行 → 漏年 + 孤立事件（吳道南 1616、曹鼐 1440、
    殷士儋 1571、許國 1583、胡廣 1412）。

## 8. 首辅等"子角色"的接入规则（暂缓）

内阁首辅不是年表字段，且**年内可多次更替**（崇祯元年五任），
不能用「年度名单第一位」自动推断。接入时必须：

1. 单独建 `office=內閣首輔` 的任职段数据，逐条标来源
   （《明史》宰辅年表 / 维基首辅列表 / 研究论著）；
2. 月份能考则考，不能考留 `NULL`；不得从名单顺序推月份；
3. 与内阁大臣数据做交叉校验（首辅必须同时是内阁大臣）；
4. 先在崇祯 17 年（demo 已验证）做基准，再向前扩。

**在通过上述校验前，正式站不显示首辅。**

## 9. 关键路径与命令

```powershell
# 数据资产（入仓）
mingoff/src/mingoff/data/vol1_entries.json
mingoff/src/mingoff/data/vol1_person_cbdb.json
mingoff/src/mingoff/data/official_cabinet.json
mingoff/src/mingoff/data/person_profiles.json

# 管线
python -m mingoff.official                 # 条目→任职段（含 D15 过滤）
python -m mingoff.build_person_profiles    # CBDB→人物小传
python -m pytest tests                     # 156 项

# 站点
cd site; pnpm build
```

## 10. 外链规范

- CBDB 人物：`https://cbdb.fas.harvard.edu/cbdbapi/person.php?id=<cbdb_id>`
  （必须带具体 id，不链到检索页空壳）；
- 中研院「明代職官資料庫」：检索是 POST，**不能把检索词编码进普通 URL**；
  正式站用隐藏表单 `POST output.php`（`input[]=人名` + `check[]=3`）新窗口提交，
  实现「一键检索《明實錄》」；并保留入口 `https://dh.rchss.sinica.edu.tw/MingChaoffTitle/`
  与检索词标注作为 POPUP 被拦截时的兜底；
- 链接一律 `target="_blank" rel="noopener noreferrer"`，并保留来源文字说明。
