# 年表 PDF OCR 规范

> 适用：张德信《明代职官年表》四册，及同版式（影印、竖排、年度表格）的续卷。
> 定位：本规范只管 **PDF → OCR 中间产物 → 源提取物（`vol<N>_entries.json`）** 这一段；
> 提取物之后的数据构建、任职段、人物对齐一律按 [数据接入规范](数据接入规范.md)。
> 立规依据：2026-10-16/17 两轮实测（册1 内阁+殿阁 386 页）与当天踩过的坑。

---

## 0. 四条铁律

1. **OCR 结果只是 L2 工作载体**，不是数据。每条入库记录必须能回答：哪一册、哪一页、哪一行。
2. **原书是唯一裁决**。OCR 缺行、错字、并格，一律回原书页核对；不得用前后年插值补齐。
3. **页级可追溯**。Markdown 没有页边界，所以「页 → 表种 → 年份 → 人」的映射必须来自
   切片清单（manifest）与原书页码，不能来自 md 行号。
4. **一次只跑一个表种**。切片、提交、解析、校验、交付都以表种为单位，不跨表种混跑。

## 2. 页码校准（每册、每次 OCR 前必做）

- 正文页码 = 页脚 `· 402 ·` 的数字；PDF 页 = 正文页 + 前置偏移。
- **册1 实测偏移 = +15**：正文 15 = PDF 30，正文 103 = PDF 118，
  正文 401 = PDF 416，正文 402 = PDF 417（页脚实拍核对）。
- 校准步骤：
  1. 用目录页读出表种起页；
  2. 在 PyMuPDF 中渲染推定页（100–150 dpi）为一页 PNG；
  3. **人眼看页脚数字 + 页眉表名**，确认偏移；
  4. 写入 manifest（见第 8 节），后续所有页码换算只用 manifest 的偏移。
- **禁止用 PDF 书签**：本 PDF 的书签是版面识别自动生成的 `1..1271` 页序号
  （实测「1 封面 / 2 书名 / … / 16 1 / 17 2…」），与正文页码无关。
- 每册偏移不同（前置页数不同），**不得跨册复用**。

## 3. 切片与提交（MinerU 云端）

### 3.1 硬限制

| 项 | 限制 | 对策 |
|---|---|---|
| 单任务页数 | 200 页 | 按表种段切片，单片 ≤200 页 |
| 单任务体积 | 200 MB | 直接切 PDF（实测 200 页 ≈ 3 MB） |
| 队列 | 约 8–16 小时 | submit 后落盘 batch_id，隔时 poll，不重复提交 |
| 输出 | Markdown（含 HTML 表格） | 只落 md，不入仓 |

### 3.2 实测基线（册1 内阁+殿阁）

- 范围：PDF 30–415（正文 15–400），共 **386 页**；
- 切片：`vol1_neige_a.pdf`（PDF 30–215，186 页，2.3 MB）、
  `vol1_neige_b.pdf`（PDF 216–415，200 页，3.2 MB）；
- 提交：2026-10-16 19:00，参数 `ocr=True, table=True, language="ch"`；
- 结果：a = 105,812 字符 / 118 个 `<table>` / 1,989 行；
  b = 155,186 字符 / 169 个 `<table>` / 2,445 行。

### 3.3 脚本约定

- 三段式：`slice`（切 PDF）→ `submit`（提交并落 batch_id）→ `poll`（查状态、下载 md）。
- **token 走环境变量 `MINERU_TOKEN`**，不得写进脚本、文档、提交记录。
- 幂等：`state.json` 记录 `batch_id / files / submitted_at`；已有 batch_id 时 submit 直接跳过。
- 命名：`_scratch/mineru_<表种>/vol<N>_<表种>_<a|b>.md`；切片 PDF 同目录。
- `_scratch/` 不入仓；入仓的只有解析脚本、`vol<N>_entries.json`、`vol<N>_manifest.json`、证据图。

## 4. OCR 输出形态（必须先预判）

MinerU 对这套年表的输出是 **HTML 表格 + Markdown 纯文本混排**，同一表种内两种形态交错：

| 形态 | 例子 | 解析要点 |
|---|---|---|
| HTML 表格 | `<table><tr><td>胡廣</td><td>四、乙亥…</td></tr>` | 按 `<tr>/<td>` 逐格 |
| 纯 Markdown 段 | `## 永樂二年 甲申 (1404)` + 逐行人名 | 按行解析，`##` 可有可无 |
| 页眉/页名 | `明代職官年表`、`內閣大臣年表`、`殿閣大學士年表` | 一律剥离 |
| 年份头 | `## 建文四年 壬午 (1402)`、`永樂元年 癸未 (1403)`、`<td colspan="2">…(1409)</td>` | 三种形态都要吃 |

已知残留问题（实测）：

1. **标题级别不稳定**：有的年份是 `##`，有的是普通行；
2. **年份头可能被并进人名格、甚至列序颠倒**（`<td>胡廣楊榮…</td><td>永樂十五年 丁酉 (1417)</td>`）；
3. **一格多名多注**：`施鳳來 張瑞圖三、癸未、廿二,加太傅致仕。…`（多人同格时名与注压成一串）；
4. **空格**：`解 繉`、`黃 淮`；**简繁混排**：`黄`/`黃`、`解繉`/`解縉`；
5. **干支误识**：`壬壬`（应壬午）、`東官`（应東宮）；
6. **无页边界**：md 不含页码，无法从 md 回溯页号 → 只能靠 manifest + 回原图。

## 5. 解析规则（按表种分列）

### 5.1 通用

1. 以 `<table>` 为单元；`<tr>` → 行；`<td>` → 格；去标签、去空格后比对。
2. **年份识别在整行/整表内做**，不依赖列位置：
   正则 `[（(](\d{3,4})[）)]`；先看本行，再看本表前两行；都没有 → 继承上一表年份（续页）。
3. 行序可信、列位置不可信：OCR 丢标签列时，**行序仍与原书一致**。
4. 人名内空格先删；注文原样保留（标点、异体、干支都不改，留给校勘层）。
5. 简繁、异体只在**比对时**归一，不覆盖原文（原文进 `raw_person`）。
6. 结构信号（月份、干支、任免动词）只用于**切分名与注**，不用于判定月份（月份判定见数据接入规范 3.3）。

### 5.2 內閣大臣年表（已跑通，可复用）

- 表页形态：`<td>姓名</td><td>注文</td>`，年份常以 `<td colspan="2">` 独占一行；
- **无注文人名行必须入库**（`<td>胡廣</td><td></td>` 或纯文本行 `胡廣`）；
- 名注未分隔：`胡廣八月，侍講` → 注文起始特征正则切分（月、官职、任免动词）；
- 多人格：`嚴嵩徐階李本` → 人名表贪心切分，切不动按姓氏兜底并记入待校清单；
- 纯文本段与表内段用两套解析器，输出同一 `entries` 结构。

#### 5.2.1 年份头错位的归属规则（2026-10-18 实测）

**不要按「年份头所在行」机械归属人名。** 表内年份头会被 OCR 挪到四种位置：

| 形态 | 实测例子 | 归属判定 |
|---|---|---|
| 年份头并入**上一年末行**，且行内有注文 | 1441 曹鼐、1572 殷士儋、1584 許國 | 人名+注文归**上一年**（注文在年份头之前） |
| 年份头并入**上一年末行**，行内无注文 | 1616 吳道南 | 若同年后文再出现同名 → 归**上一年** |
| **裸名行**紧挨在年份头之前，上一年已有该人带注文行 | 1412 胡廣（原书 p19） | 该名归**下一年**；原书核对后 `book-patch` 补录 |
| **一格多名**（无注文整名单）+ 年份头 | 1417/1458/1488/1518 | 归**本年**（名单即本年 roster） |
| 单人名 + 纯年份头、后文无同名 | 1618/1619 方從哲 | 归**本年** |

判定存疑时一律回原书页，禁止用前后年插值。审计脚本（已用于册1）：
`_scratch/audit_year_merge.py`（年份头+人名同行）、`audit_tail_name.py`
（年份头前裸名且上一年已有带注文行）。

### 5.3 殿閣大學士年表（版式测绘先行）

结构（实拍核对）：

- 每页 = 一年（少数页含两年）；
- 行 = 官职：**華蓋殿 / 謹身殿 / 文華殿 / 武英殿 / 文淵閣 / 東閣**
  （嘉靖四十一年后改稱 **中極殿 / 建極殿**，其余沿用），
  其下为 翰林院 4 行（翰林學士、侍講學士、侍讀學士、直學士）+ 國子監祭酒（+ 南京國子監祭酒）；
- 格 = 该年该职在任者，**多人为多列**；同一人年内迁转另起一行；
- 标签列常整列丢失（`<td colspan="7">`），跨页续行常见。

解析纪律：

1. 先渲染 3–5 页原图，标出「标签列 / 六殿阁行 / 翰林行」，写进版式说明再写代码；
2. 有标签按标签归类；**无标签按行序补**：每页前 6 个职位行 = 六殿阁；
3. 续页（表内无年份头）继承上一表年份，且必须先确认该页属于同一表种；
4. 只用六殿阁行 → 得「殿阁衔 / 班次 / 首辅」；翰林院与祭酒行单列，属人物履历层，
   不与内阁数据混表；
5. 可行性探针（2026-10-17）：殿阁段 254 表 / 有年份头 242 年，120 表带标签；
   抽样锚点与史实一致（1424 華蓋殿 楊士奇、1552 嚴嵩、1562 中極殿 嚴嵩、
   1572 張居正、1584 中極殿 申時行…）。版式实拍：
   [嘉靖四十二年页](evidence/book_p301_diange1563.jpg)、
   [崇祯元年页](evidence/book_p375_diange1628.jpg)。
6. 殿阁大学士始置于洪武十五年（1382，華蓋殿劉仲質），早于内阁（1402），
   所以本表左端 1382–1401 有内容，不能因为「内阁未设」而跳过。

### 5.4 部院大臣 / 侍郎 / 京卿（册1 后续）

- 版式同 5.3：年 × 官职行（吏/户/礼/兵/刑/工 部、都察院等），格内多名；
- 先做版式测绘；**不得**直接套 5.2 的「姓名+注文」两列假设。

### 5.5 中書省大臣年表（册1 第 1–14 页）

- 行 = 丞相（左/右）、平章政事、丞（左/右）、参知政事；格内多名；
- 14 页、洪武元年–十三年（1368–1380），量小，适合作新解析器的试点
  （版式实拍：[洪武元年页](evidence/book_p2_zhongshu.jpg)）；
- 洪武十三年胡惟庸伏诛、废中书省，是全表的自然终点。

### 5.6 册2–4（六科 / 南京 / 督抚 / 布政 / 科举）

- 一律先版式测绘，再写解析器；每表种独立登记、独立校验；
- 册4 附錄人物小传与 CBDB 重叠，**不入结构化**（避免双源混写）。

## 6. 缺块与补录（`BOOK_PATCH`）

**触发**：某年整块缺失、某年人数显著少于前后、名人锚点缺失（如 1403 解縉）。

**处置**：
1. 用 manifest 页码渲染原书页为 PNG；
2. 人工逐行转录（或二次 OCR 该页）；
3. 以 `src="book-patch"` 写入提取物，保留 `raw_person`；
4. 证据图存 `docs/evidence/`，文件名带正文页码；
5. 在报告中登记「哪年、缺什么、依据哪页」。

**禁止**：用前后年名单插值、用二手列表（维基/明史）冒充原书补录。
二手源只能作为「该校有此人的旁证」，不能写进 `book-patch` 的名单。

已有先例：1403 解縉补行、1408 / 1412 胡廣 / 1424 / 1479–81 / 1515 / 1567 / 1609–11
（见 `_scratch/rebuild_parse.py` 的 `BOOK_PATCH`；入仓后该表迁入正式解析脚本）。

## 7. 校验门（O1–O6，OCR 层，全过才允许生成提取物）

| Gate | 检查 | 阈值 / 处理 |
|---|---|---|
| O1 页覆盖 | 每片输出非空；页数×0.9 ≤ 表数；页眉/页脚抽样一致 | 不足则重跑该片，不得用邻片结果补 |
| O2 年份连续 | 该表种覆盖年 100%；缺年逐条归因（OCR 丢 / 续页 / 原书缺） | 归因不清 → 回原图，不得放过 |
| O3 行完整 | 每年人数与相邻年中位数偏离 >50% 预警；统计无注文行占比 | 异常年逐页核对 |
| O4 名归一 | 人名归一率 ≥99%；变体进别名表；`(year,person)` 唯一 | 未归一的进待校清单 |
| O5 人工抽检 | 每表种随机 10 页 + 名人锚点 ≥10 个（楊士奇/嚴嵩/徐階/張居正/崇祯诸臣），对照原图 | 证据图与结论写进报告 |
| O6 归属 | 年份头+人名同行的行逐条判定（5.2.1）；同人逐年名单无「无法解释的中间缺年」；名单骤降点回原书核对 | 可疑行/年入审计清单，回原书页 |

O1–O6 通过后，提取物才进入数据接入规范的 G1–G5。

## 8. 中间产物、命名与 manifest

```
_scratch/mineru_<表种>/
  vol<N>_<表种>_<a|b>.pdf     # 切片（不入仓）
  vol<N>_<表种>_<a|b>.md      # OCR 结果（不入仓，体积+版权）
  state.json                  # batch_id / files / submitted_at（不入仓）

src/mingoff/data/
  vol<N>_entries.json         # 源提取物（入仓）
  vol<N>_manifest.json        # 溯源与校验（入仓）
```

`vol<N>_manifest.json` 必填：

```json
{
  "source": "张德信《明代职官年表》册N（扫描 PDF）",
  "pdf_pages": 1281, "offset": 15,
  "table": "內閣大臣年表", "book_pages": [15, 102], "pdf_range": [30, 117],
  "slices": [{"file": "vol1_neige_a.pdf", "pages": 186, "chars": 105812,
              "tables": 118, "rows": 1989}],
  "tool": {"name": "MinerU", "params": {"ocr": true, "table": true, "language": "ch"}},
  "submitted_at": "2026-10-16T19:00:16+08:00",
  "gates": {"O1": "pass", "O2": "pass(缺年: …)", "O3": "pass", "O4": "pass",
            "O5": "pass", "O6": "pass(同行行 20 / 裸名 2)"},
  "evidence": ["docs/evidence/book_p108_chongzhen1.jpg"]
}
```

## 9. 新表种接入清单（照抄执行）

1. **校准偏移**：目录页 → 渲染 3 页 → 读页脚 → 写 manifest；
2. **切片**：按表种整段切，≤200 页/片；
3. **提交**：`MINERU_TOKEN` 环境变量，submit 后落 `state.json`；
4. **落 md**：保存字符数、表数、行数；与切片页数比对（O1）；
5. **版式测绘**：渲染 3–5 页原图，标出官职行、标签列、跨页续行规则；
6. **写解析器**：通用规则（5.1）+ 该表种规则（5.2–5.6）；
7. **跑 O1–O6**：缺年、异常人数、名归一、归属判定、抽检，全部留证据；
8. **出提取物**：`vol<N>_entries.json`（`year/person/note/src/raw_person`）；
9. **过 G1–G5**：进数据接入规范；
10. **提交**：解析脚本 + 提取物 + manifest + 证据图 + 报告数字，同一次提交。

## 10. 反模式（逐条来自实测）

1. 用 PDF 书签当正文页码——书签是自动生成的 1..N；
2. 用 md 行号当页号——md 无页界，页级问题只能回切片/原图；
3. 把「无注文」当「无任职」——年表逐年列名，无注文只是「本年无事」；
4. 只解析有注文的行——上一轮 360 段假碎片就是这么来的；
5. 依赖列位置取人名/年份——年份会跑到第二格、甚至与人名同格；
6. 把注文里的跨年事件算到当年（永乐五年注里的「萬曆十八年…」）；
7. OCR 变体直接入库（解繉、黄淮、林釘）——必须先归一、留 `raw_person`；
8. 用「年表首位」推首辅——首辅要靠殿阁衔/班次，不能靠名单顺序；
9. 一次提交整册 1000+ 页——超限、排队失败、无法定位；
10. 把 token、商业库全文、未授权 OCR 结果提交进仓库。
