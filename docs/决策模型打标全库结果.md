## 三、必须记下的坑：`is_tenure` 在全库尺度上失效

**数据**：全库 4,266 条判为「授官」的条目里，**4,190 条（98.2%）同时被判 is_tenure=否**；
反过来 is_tenure=是 的仅 76 条，**且全部来自 kind=授官**。

**这不是抽样噪声，是系统性翻转**：同一段文本，单条测试时判"是"，全库成批跑时判"否"。
典型的「陞翰林院侍讀學士王錫爵為國子監祭酒」被 kind 判为授官（conf 0.82）而 is_tenure 判否。

**影响**：

- `is_tenure` 这一列**全库不可用**，已从索引字段中剔除；
- 试点（300 条金标准）里 is_tenure 的 85%/96% 数字**只在当次单跑设定下成立**，不可外推；
- `kind` 与 5 个附加布尔标签**没有**同样问题（授官 4,266 条的 kind_conf 分布正常，conf≥0.9 有 2,226 条）。

**教训（写进规范）**：决策模型一次问 ≥8 个问题时，**语义相近的两个问题会互相污染**
（"是否任职史料" 与 "是否授官" 在语义上高度重合，模型被迫在二者间做排他解读）。
**每次请求的问题之间必须互斥**，否则要分两次请求。

## 四、可用姿势（基于全库结果）

| 用途 | 做法 |

| 「谁在任」的候选集 | `kind∈{授官, 离任}` 且 conf≥0.9，共 2,280 条 |

| 反例池 | `kind=其他` 且 military=是（军事类）不能用于任职，需在检索中排除 |

| 项 | 试点（300 条金标准） | 全库 |

kind 的占比与置信结构在全库上复现了试点的结论，**唯一翻车的是成批多问的 is_tenure**。
