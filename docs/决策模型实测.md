## 二、能力边界（实测数据）

### 2.1 三题型正常

```
department: choice  billing  confidence 0.88  P={billing 0.94, technical 0.06}
escalate:   noul    P(yes)=0.99
severity:   score   2.25      confidence 0.91
```

### 2.2 明代人物常识：不可信

问法："state（人名）是否担任过明代 X 尚书？"

| 人名 | 问法 | P(yes) | 史实正解 | 判定 |
|---|---|---|---|---|
| 朱厚照 | 是否明代皇帝 | **0.33** | 是（正德帝） | ❌ 反了 |
| 朱厚照（改问"正德帝姓名"） | 同 | 0.40 | 是 | ❌ |
| 胡濙 | 是否礼部尚书 | 0.80 | 是 | ✅ |
| 張守魁（不存在） | 是否礼部尚书 | 0.06 | 否 | ✅ |
| **王振** | 是否兵部尚书 | **0.89** | **否**（司礼监太监） | ❌ 高置信误判 |
| 于謙 | 是否兵部尚书 | 0.90 | 是 | ✅ |

**"正德帝叫什么"这种常识级问题都答不对，且错的时候置信度并不低。** 这说明它是任务判别模型，不是检索/知识模型；但它对**上下文里的**文字做判断是靠谱的（2.3）。

### 2.3 长文本：能吃，也能判

14,800 字（13,218 tok）的《明实录》体量文本，问"是否在叙述明代史事"→ **P(yes)=0.99**，783 ms。
上限 65,536 tok，够一整卷实录；但"判别"只能做粗粒度，细到"这句里谁在哪一年任什么"它不行。

### 2.4 缺表头行 → 衙署归属：**看似可行，实则是按提示词附和**

给一段编造的 1409 年表（吏/戶/禮/兵/刑/工 六行标好），最后加一行没标签的「御史臺　顧佐」，问它归哪个衙：

```
→ 都察院   confidence 0.84   P(都察院)=0.86
```

**这一条差点骗过我自己**：它"答对了"，但史实是——永乐七年（1409）都察院已改称御史臺，正确的标签应是「御史臺」。它答"都察院"是因为**行文里我自己写了"御史臺"三个字**，它跟着复读了。

**教训**：它的 choice 置信度不衡量事实正确性，只衡量"输入里有没有明确指向"。
任何"它知道答案"的错觉，都必须先做一次**把关键线索删掉**的对照实验。

### 2.5 D-04 场景实测：同一事实换个说法就翻脸

D-04 里最典型的一条：1550 年总督京儲/倉場页无表头（续页），按原书规则应继承 1549 的「總督京儲」，
数据现状是把 1550 挂在了「總督倉場」。给它同样的年度成员，只换线索变量：

| 条件 | 模型选择 | 置信度 | 应判 |
|---|---|---|---|
| A 只给 1550 成员 | 无法判断 | 0.46（对） | ✅ 诚实说不清 |
| B 我提示"1549 是總督京儲" | **總督京儲** | 0.93 | ✅ 附和 B |
| C 我提示"1551 是總督倉場" | **總督倉場** | 0.87 | ✅ 附和 C |
| D 把两个都给它，并明说"续页继承" | 總督倉場 | 0.45 vs 京儲 0.37 | ❌ 50/50，略偏向错的那个 |

**B 与 C 是同一件事的两个提示，它给出方向相反的高置信答案。** 换句话说：
**它的"判断"由我写进 state 的线索决定，而不是由它对明代制度的理解决定。**
这种情况下用它，等于把我自己的判断绕一圈还给我，还披上一层 0.9 的置信度外衣——
在"每条记录都要说清自己有多可信"的项目里，这是**负价值**。

## 三、对 MingOff 的价值判断

| 场景 | 可用性 |
|---|---|
| D-04 表头核 / 原书页比对 | ❌ 不可用（2.5）：史实判断依赖提示，且易被原文措辞诱导 |
| 明人传记索引抽取（OCR 错字、切分边界） | ❌ 不适用：这是抽取/纠错，不是分类；模型对没有明确线索的输入只能附和 |
| 人物同名消歧 | ⚠️ 不可用：需要生卒/籍贯史实（2.2 已证不可靠） |
| **站点上线后的内容分类**（如"这条史料出处属于墓志/传记/官录"） | ✅ 可用：判据就是文本特征，与史实无关 |
| **审核/净化**（投稿垃圾串、异体字混杂、非人名碎片） | ✅ 可用：这类判据几句话说清，模型足够 |
| **Agent 路由**（"这条要回原书页核"vs"这条走规则即可"） | ✅ 可用：但收益要有实际调用量才体现 |

## 四、工程要点（真要接时看）

- **Key 不在环境变量里**：现在要 `export DASHSCOPE_API_KEY=...` 才符合文档前置条件。
  建议直接写进 `~/.dsh/settings.yaml` 或项目 `.env`，**不要**进 git。
- **云点**：`{WorkspaceId}.maas.aliyuncs.com/compatible-mode/v1/systemone`；本机 key 指向专属 host，
  实测能通（说明该 key 同时具有公网百炼网关权限）。
- **一次最多问 16 个问题**，延迟近线性；批量分片按 16 裁。
- **只计输入 token**：所以**别把宝押在"多问几个问题摊薄成本"**——问题越多 state 越长，成本按输入走。
- 限时免费期间可以试，但**不能让它进数据管线**：见 2.4、2.5，它的置信度不能当项目里
  `confidence` 字段用，因为那个字段的语义是"史料多可信"，不是"模型多确定"。
