# 决策模型打标试点报告（D39）

> 2026-10-19。用 `decision-model-preview`（choice 多选一 + 选项描述）给《明实录》条目打标，
> 目标是回答一个问题：**它能不能当批量打标机，替代/辅助我们的规则**。
> 脚本：`scripts/pilot/pilot_tag.py`（500 条随机抽样）、`scripts/pilot/gold_check.py`（金标准 300 条）、
> `scripts/pilot/analyze_pilot.py`、`scripts/pilot/analyze_gold.py`。
> 数据：`src/mingoff/data/pilot_tag_out.json`、`pilot_gold_out.json`、`pilot_manual_check.md`（未入 git 的中间产物随报告一并提交）。

## 一、结论先行

| 问题 | 答案 |
|---|---|
| 能不能当批量打标机？ | **能，但只能当"高置信度筛子"，不能当裁判**：置信度 ≥0.9 的判定准确率 **96.7%**，置信度 <0.7 的只有 **47.4%**（等于抛硬币） |
| 识别"任职史料"准不准？ | **正类召回 83%、精确率 98.8%、总体准确率 91%**（金标准 300 条） |
| 能不能识别"议政 vs 其他"？ | **弱**：规整的议政文本只判对 50%，其余 42% 被丢进"其他"（安全但无用） |
| 能不能识别"加衔/褒赠/赐予"？ | **不能**：100 条边界样本里 77% 判"其他"、11% 判"授官"，**方向不稳定** |
| 速度与成本 | 500 条 108 秒 / **208,359 tokens**（416 tok/条，含 4 问）；全库 27,544 条约 1,146 万 tokens |

## 二、试点设计

### 2.1 随机抽样 500 条（`pilot_tag.py`）

从 `sinica_all.json`（502 人 / 27,544 条）随机抽 500 条，每条一次请求问 4 个问题：

| 问题 | 类型 | 用途 |
|---|---|---|
| kind | choice 5 选项 | 授官 / 离任 / 议政 / 行政 / 其他 |
| is_tenure | choice 是/否 | 是否任职史料 |
| leave | choice 是/否 | 是否记载离职 |
| clarity | score 0–3 | 任职信息明确度 |

同时跑三条**规则对照**：
- R1 `句首任免动词 + 官职`（陞/授/改/擢/遷/除/補 … 20 字内出现官职词），命中率 **8.6%（2,363 条）**
- R2 `离任动词`（致仕/乞休/罷/削籍/奪職/卒/降級）
- R3 `议政动词`（言/議/奏/疏/請）

### 2.2 金标准 300 条（`gold_check.py`）

随机样本里"正类"太少（授官只占 16%），无法量准确率，所以另建**100% 可判**的样本：

| 组 | 构造规则 | 应有判定 | 条数 |
|---|---|---|---|
| GL_pos | 句首任免动词 + 官职（R1 命中） | 授官 / 是 | 100 |
| GL_neg | 无授官动词，且含议政词 | 议政 / 否 | 100 |
| GL_edge | 无授官动词，但含 加/兼/贈/賜/蔭 | 有争议（只观测） | 100 |

## 三、结果

### 3.1 金标准（模型打标 vs 可判样本）

| 组 | 指标 | 数值 |
|---|---|---|
| GL_pos（n=100） | kind=授官 | **83.0%** |
| | is_tenure=是 | 85.0% |
| | **置信度 ≥0.9 的子集（n=60）** | **96.7%** |
| | **置信度 <0.7 的子集（n=19）** | **47.4%** |
| GL_neg（n=100） | kind=议政 | 50.0%（其余 42% 判"其他"） |
| | is_tenure=否 | **96.0%** |
| GL_edge（n=100） | kind 分布 | 其他 77 / 授官 11 / 离任 6 / 议政 5 / 行政 1 |

**二分类（授官 vs 非授官）**：TP=83 FP=1 FN=17 TN=99 → **精确率 98.8%、召回 83.0%、准确率 91.0%**。

### 3.2 关键发现：置信度是可靠的"筛子"

这是本轮最有价值的结论：

```
conf ≥ 0.9  → 准确率 96.7%（可直接采信）
conf < 0.7  → 准确率 47.4%（不要采信，退回规则/人工）
```

**用法**：全库打标后，只采信 `kind_conf >= 0.9` 的判定（新版模型很克制：随机 500 条里只有 **17%（85 条）** 达到 0.9；正类里也只有 60% 达到 0.9），剩下 40% 不强行判，
直接留给规则或人工。这样"自动判定"那部分几乎不出错。

### 3.3 典型误判（看它错在哪）

**漏判（GL_pos 被判成其他）**：
- `○陞甘肅守備熊國臣寧夏遊擊大寧都司掌印許國忠宣府參將…` → 判"其他"：武职任命，它把"守備/遊擊/參將"当军事
- `○陞重慶衛指揮僉事王獻為安陸衛指揮同知賜鈔六十錠…` → 判"其他"：**卫所武官**它也不认
- 其余多为"陞一批官职但不带'為'"的简写语序

**误判（GL_neg 被判成授官）**：
- `○己酉命太常寺少卿兼翰林院侍讀彭時陞兼翰林院學士改通政司左參議兼翰林院侍講呂原…` → 这一条**确实是任命**，
  只是没以任免动词开头。**说明我的"句首动词"金标准本身会漏**——规则 R1 的规则比模型粗。

### 3.4 随机样本的分布（500 条）

| kind | 条数 | 占比 | 平均置信度 |
|---|---|---|---|
| 其他 | 252 | 50.4% | 0.687 |
| 议政 | 121 | 24.2% | 0.649 |
| 授官 | 82 | 16.4% | 0.775 |
| 行政 | 25 | 5.0% | 0.502 |
| 离任 | 20 | 4.0% | 0.634 |

模型判"授官"的 82 条里，**41 条规则 R1 没命中**（模型召回 95.3%，规则 R1 精确度 50%）——
**模型能抓到规则漏掉的授官写法**，这是它相对规则的真正增量。

## 五、建议

1. **可用场景**：全库打 `kind` 标签，**只采信 conf ≥ 0.9**（随机样本里约 17% 条目可自动定类，其余留给规则/人工），
   其余留人工/规则。作为站点检索筛选（"只看任命条目"）已经够用。
2. **不要用**：判"加衔 vs 授官"、判武官任命、判"谁任了什么"——这三类它错得没有规律。
3. **注意金标准本身的盲区**：句首动词规则会漏掉"命…陞…"这类写法，做全量规则时应补一个"句中任免动词"通道。
4. **人工核对清单**：`src/mingoff/data/pilot_manual_check.md`（62 条）留给老板抽查，
   我没替你判——**准确率数字是相对"构造金标准"而言，不是人眼金标准**。
