## 二、推荐方案：一私有 + 一公开（Tier B）

### 1. 私有仓：`mingoff-archive`（立即建，解决单副本）

- 内容：**当前全量**（代码 + 全部数据资产 + docs/evidence + mrzj + .workbuddy + 历史）；
- 可见性：Private；
- 作用：备份、可回溯、内部研究；
- 大小：74MB，GitHub 私有仓免费额度内（单文件 <100MB，仓 <1GB）。

### 2. 公开仓：`mingoff`（整理后建）

- 内容：代码 + 站点 + 设计文档 + **精简结构化数据**（约 **10–11MB / 170+ 文件**）；
- 历史：**干净初始提交**（不复用私有仓 53 个提交，避免历史泄露已删文件）；
- 可见性：Public（先让老板确认 Tier B 的数据版权口径）；
- 站点：Vercel（推荐，push 即部署）或 GitHub Pages + 自定义域名。

## 三、公开仓的版权口径（需老板拍板）

| 方案 | 内容 | 风险 | 建议 |
|---|---|---|---|
| **A 最稳** | 公开仓只放代码 + 示例数据（崇祯兵部尚书 14 任 + 少量段）；全量数据只在私有仓 | 最低；但公开站功能受限 | 若不想碰版权，选 A |
| **B 研究性公开（推荐）** | 公开代码 + 站点 + 本项目整理的结构化数据（`official_*.json`/`person_profiles*.json`/`vol1_*`），**不含扫描/OCR/全文**；CC BY-NC-SA + 署名 + 移除声明 | 中：张德信年表衍生数据的版权需自担；学术非商业用途+署名+可移除是常见做法 | 先按 B 上线，保留 take-down |
| **C 全量** | 连 OCR/扫描页/索引 OCR 一起公开 | 高：明确侵犯现代出版物版权 | **不推荐** |

B 方案的前置动作：
1. 在 `official_*.json` 的 `meta` 增加 `license: "CC BY-NC-SA 4.0"` 与来源声明（D11 要求每个数据文件可识别许可）；
2. README 顶部写明「非商业研究项目 / 数据许可 / 第三方来源 / 可移除」；
3. 公开仓不含 `docs/evidence`、`mrzj`、`sinica`、`web/demo.html`、`.workbuddy`；
4. 如需更稳，可先给黄山书社/作者方发一封说明邮件（非必须，但留痕）。

## 四、CI / 部署

### CI（`.github/workflows/ci.yml`）

- Python 3.13（本地 3.14；代码兼容）；`PYTHONPATH=src pytest -q`；
- Node 24 + pnpm 11；`site/pnpm install --frozen-lockfile` + `pnpm build`；
- 私有仓跑全量测试；公开仓 mrzj 测试自动 skip。

### 部署

| 方案 | 做法 | 优劣 |
|---|---|---|
| **Vercel（推荐）** | GitHub 集成，push 即部署；根目录 `site/`；无需 basePath | 零运维；与 `yinyizhuan` 同套路；免费额度足够 |
| GitHub Pages + 自定义域名 | Actions 构建 `site/out`；CNAME 到 `Tomorin-1122.github.io`；无 basePath | 免费、稳定；需配 DNS |
| GitHub Pages 项目路径 | `https://tomorin-1122.github.io/mingoff/` | 需给 Next 加 `basePath`，站内绝对路径要改；不推荐先做 |

> 站点是静态导出，数据全在客户端 JSON 里；**公开站 = 数据公开**，所以 Tier A/B/C 的选择同时决定站点能否公开。
