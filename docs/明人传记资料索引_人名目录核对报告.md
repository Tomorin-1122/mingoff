## 二、与正文对校

判定规则：目录说「某人见 pX」，就去正文 pX 的 OCR 文本里找。

| 状态 | 人数 | 占比 | 含义 |
|---|---|---|---|
| **ok** | **6,389** | 66.2% | 正文该页逐字有此名 |
| **fixed** | **145** | 1.5% | 同页同长、一字差、且唯一 → 可定向改正 |
| ocr_variant | 2,520 | 26.1% | 同页有近名，但多对一或长度不一，证据不足 |
| page_mismatch | 31 | 0.3% | 全书有条目，但不在目录所标页 |
| name_missing | 566 | 5.9% | 该页与全书皆无 |

### 2.1 可定向改正的 145 条（样例）

左边是目录（＝原书正确写法），右边是正文 OCR 现状：

```
p12  方孝友 → 方寧友        p85  孔間韶 → 孔聞韶
p15  方宸孺 → 方震孺        p60  王舜耕 → 王疑耕
p23  王允成 → 王尤成        p76  王勵精 → 王顯精
p130 朱埕爵 → 朱承爵        p124 朱曰藩 → 朱日藩
```

典型成因：形近字（聞/間、震/宸、允/尤）、OCR 掉字或添字。

### 2.2 为什么还有 2,520 条「证据不足」

同页往往有 15–20 个条目，一字之差的名字可能撞上别人。例如「王衡」「王幸」
「王紳」都曾被匹配到同页的「王冕」——这显然是错的。所以这一档**不自动改**，
必须人工或第三方源定夺。

### 2.3 566 条「该页与全书皆无」

两种可能：目录 OCR 把名字认错了（INDEX 本身也有错字），或正文漏行。
这批需要回原书页看图，是目前最大的不确定块。

## 三、这次校对解决了什么

1. **确认了目录规模**：9,651 人，与旧估「8,000–10,000」相符；
2. **拿到 145 条可直接修的正文 OCR 错字**，这是纯收益；
3. **建立了「页 ↔ 人名」的双向索引**：以后任何一条正文 OCR 都能按页反查目录名；
4. **暴露了 566 个待查点**，比原来「不知道哪里错」进了一步。

没能解决的：字体层面的形近混淆（聞/間、日/曰、允/尤）靠规则判不了，
必须有第三方源（CBDB、明史、原书页图）仲裁。

### 4.2 罗马字可以定姓氏（新发现）

INDEX 每条都带 Wade-Giles，这给了一条独立线索。典型错例：

| 目录 OCR | 罗马字 | 实为 | 依据 |
|---|---|---|---|
| 卜榮（p18） | Pien Jung | **卞榮** | 卞 的页段是 18–19，卜 是 5–6 |
| 末端儀（p184） | Sung Tuan I | **宋端儀** | 回原书页 p184，正文赫然作「宋端儀(1447—1501)字孔時」 |
| 宠恭（p502） | K'ou Kung | 寇恭 | 寇 的页段起于 502 |

方法：同一罗马字下的姓氏做统计，再看候选姓的页段是否覆盖该页，
**候选唯一**才提出。共产出 103 条提案，其中 **23 条经正文验证成立**，已固化；
其余 80 条多解或正文对不上，不动。

## 五、第三轮：本地 CBDB 裁决（2026-10-18 晚）

用 `_cbdb/cbdb_20261010.sqlite3`（66.3 万人，其中**明代 22.56 万**，`c_dy=19`）
对 3,138 条存疑名做裁决，只看明代，不跨朝。

### 5.1 裁决结果

| 判定 | 条数 |
|---|---|
| 唯一命中（正名在库，一人） | 871 |
| 命中我们已校过的 cbdb_id | 91 |
| 别名命中（字号 → 正名） | 5 |
| 同名多人、无法定夺 | 824 |
| **CBDB 无此人** | **1,327** |

共 **967 条**拿到 CBDB 编号与正名，可写入目录。

### 5.2 反向校验我们自己的数据

拿 MingOff 已对齐的 cbdb_id 回查 CBDB 正名，**只有 2 条不一致**——
部院/内阁那套 960 个编号是干净的。

### 5.3 一个必须说清的坑

本想用「索引名在库、正文变体不在库」反判正文错字，筛出 235 条，
但抽样发现大量变体是**称谓碎片**而非人名：

```
丁公 → 丁賓      方公 → 方璘      孔公 → 孔鏞
白君 → 白瑩      石公 → 石星
```

「丁公」来自出处「丁公墓誌銘」，不是人名。条目人名抽取里有 2%（268/13,176）
是这类称谓尾巴，一字差规则一撞就误判。

**结论：这批 235 条不能自动回写正文**，得先把条目人名抽取的称谓过滤补上
（公/君/母/氏/太/父），再重跑三轮。

### 5.4 称谓过滤后的复核

补上过滤后重抽条目人名：13,176 → **13,035**（剔掉 141 个称谓碎片）。
同一套筛选条件再跑，「索引名在库、正文变体不在库」的候选从 **235 条塌到 1 条**：

```
p500  郭鎧 → 郭灌（id 130208）
```

证明那 235 条几乎全是题名碎片，自动回写确实不该做。

### 5.5 全目录 CBDB 覆盖

把 9,651 个目录名整体过一遍 CBDB（只认明代）：

| CBDB 结果 | 人数 | 占比 |
|---|---|---|
| 唯一命中 | 3,789 | 39.3% |
| 同名多人 | 4,033 | 41.8% |
| **合计在库** | **7,822** | **81.0%** |
| 无此人 | 1,829 | 19.0% |

「无此人」的多为布衣、隐逸、女性、方外，本就不在 CBDB 官员库里，属正常边界。

### 5.6 最终置信分层

| 层级 | 人数 | 占比 | 含义 |
|---|---|---|---|
| **A 逐字 + CBDB** | **6,034** | 62.5% | 正文该页有此名，CBDB 亦为明代人物 |
| B 逐字 | 510 | 5.3% | 正文有，CBDB 无（多为非官员） |
| C 已定向改 | 12 | 0.1% | 经一字差修正后确认 |
| D CBDB 有、正文待对 | 1,779 | 18.4% | 人名真实，但与正文页对不上 |
| E 待查 | 1,316 | 13.6% | 正文与 CBDB 都未落地 |

**A+B+C = 6,556 人（67.9%）可视为已落地**；加上 D 层的「人名真实」，
共 8,335 人（86.4%）至少有 CBDB 或正文之一背书。

### 5.7 D 层攻坚：1,779 → 1,689

D 层是「CBDB 认人名、正文对不上页」。拆开看：

| 情形 | 条数 | 处理 |
|---|---|---|
| 别页有本人条目（条目开头） | 69 | **直接改页**，全部落在姓氏区间内 |
| 同/邻页有此名但未识别为条目 | 37 | 只取相差 1 页的 **21 条**，2 页差不动 |
| 仅远端引用（别人条目里提到） | 254 | 不动 |
| 全书无此名 | 1,419 | 仍需回图或第三方 |

改页后：`page_mismatch` **31 → 0**，`ok` 6,544 → **6,634**。
典型修正：

```
林文俊 p2 → p289      郁新 p60 → p360      汪仲魯 p16 → p162
丁政 p2 → p3          方鼎 p16 → p15       文元發 p15 → p16
```

多为目录页码掉位（60→360、16→162）或相邻页错位（±1）。

## 七、口径与纪律

- 目录只作**校勘层**，不替代正文条目；生卒/官职仍以正文小传为准；
- 一条目录名若不唯一（多页），不合并，标 `multi_page` 留待拆；
- 简体混入（黄/黃、吕/呂 共 200 人）已做归一，映射表写在脚本里；
- 所有判定都可复现：`_scratch/mrzj_index.py` 重跑即可；
- 修正分两层：`corrections.json`（正文侧 145 条）、`confirmed_roman_fixes.json`
  （目录侧 23 条），都不改原始 OCR 产物。
