## 一、结论速览（更正版）

| 需求 | 数据源 | 实测结论 |
|---|---|---|
| **精确到月** | 中研院 `output.php check[]=3` | ✅ **支持，覆盖率 100%** —— 月份在「出處」列 |
| **精确到月** | CBDB 快照 | ❌ **不支持** —— 字段存在但填充率 1.2%，且多为 `0月` |
| **扩展到其他职官** | CBDB 快照 | ✅ **支持** —— 34,271 个官职（含地方官） |
| **扩展到其他职官** | 中研院 `check[]=2` | ✅ **支持** —— 含「官職隸屬部門」「官職隸屬類型」 |

**一句话**：月度精度取自中研院；CBDB 提供广度与官职树，但不提供月份。

## 二、CBDB 实测细节

### 2.1 快照获取（已验证可信）

```
下载: https://huggingface.co/datasets/cbdb/cbdb-sqlite/resolve/main/history/cbdb_202610/cbdb_20261010.zip
大小: 139.4 MB (zip) → 560 MB (解压后 .sqlite3)
SHA-256: b43de31b298546ad8605ab52cd78d2a70d7b946abc01bf0d4efd18dd7853782d  ✅ 完全匹配
```

> ⚠️ 注意 `latest.json` 里的 `sha256` 是**解压后 .sqlite3** 的哈希，不是 zip 的。
> 直接校验 zip 会误判为"下载损坏"。实测踩过这个坑。

### 2.2 表规模

| 表 | 行数 | 说明 |
|---|---|---|
| `BIOG_MAIN` | 662,861 | 人物主表 |
| `POSTED_TO_OFFICE_DATA` | 592,022 | **任职主表** |
| `OFFICE_CODES` | 34,271 | 官职字典 |
| `ENTRY_DATA` | 265,279 | 入仕记录 |
| `OFFICE_TYPE_TREE` | 2,742 | 官职树 |

### 2.3 月份字段填充率（关键否证）

`POSTED_TO_OFFICE_DATA` **确实有**月份字段：

```
c_fy_month  (起始月)   c_ly_month  (离任月)
c_fy_day    (起始日)   c_ly_day    (离任日)
c_fy_intercalary (是否闰月)
```

但全表 592,022 行中：

| 字段 | 非空数 | 占比 |
|---|---|---|
| `c_firstyear` | 428,248 | 72.3% |
| `c_fy_month` | **6,150** | **1.0%** |
| `c_ly_month` | 5,175 | 0.9% |

**崇祯朝（1628–1644）2,676 条记录中，起始月仅 31 条 = 1.2%。**

### 2.4 那 31 条月份记录能用吗？——不能

实测样本：

```
朱燮元  兵部尚書  起 16286月        ← 「6月」被存成 0 月
俞伯珠  典史      起 16280月        ← 0 月，且是地方小官
陳奇傑  通判      起 16280月
魏士清  府通判    起 16330月
```

两个问题：
1. **大量 `0月`** —— 是"月份未知"的占位，不是真值；
2. 有月份的**几乎全是地方小官**（典史/教谕/县丞/知县/主簿），
   我们关心的**中央要职一条都没有**。

### 2.5 但 CBDB 的官职覆盖确实广（支持扩展）

崇祯朝中央要职在 CBDB 的记录数：

| 职位 | CBDB 记录 | 有月份 | 涉及人数 |
|---|---|---|---|
| 兵部尚書 | 34 | 1 | 29 |
| 禮部尚書 | 15 | 0 | 15 |
| 吏部尚書 | 8 | 0 | 4 |
| 戶部尚書 | 7 | 0 | 7 |
| 刑部尚書 | 7 | 0 | 6 |
| 工部尚書 | 7 | 0 | 6 |
| 都察院左都御史 | 4 | 0 | 3 |

**职称总数 34,271 个**（含地方官），可支撑"扩展到其他职官"。

> 🔎 **交叉印证**：CBDB 的兵部尚书样本里出现了 **袁崇煥**，而 PRD 12.2 明确
> 把他列为"带兵部尚书衔的督师，非京中兵部尚书"应予排除。**CBDB 收了他**，
> 说明直接用 CBDB 数据会引入 PRD 要求排除的人 —— 这正是需要校勘层的原因。

### 3.1 `check[]=3`（明實錄）—— 月度精度的来源

实测检索「楊嗣昌」：

```
時間    年號    出處        卷次        內容
1613   萬曆    明實錄 神宗  卷五百十五   萬曆四十一年十二月 ○禮部會同九卿科道會勘庚戌塲獘…

**质量评价**：
- ✅ 有**年 + 月**（「萬曆四十一年十二月」），且是**原文可引用**

- ✅ 检索词可任意（人名/官职）
- ⚠️ 返回是 **HTML 表格**，单次 4~6 MB，需流式解析
- ⚠️ 需注意：可检索性受站点限制，非结构化遍历接口

### 3.2 `check[]=2`（官職）—— 官职树与隶属关系

```
姓名    原始紀錄              整理後紀錄      隸屬部門門下  官職隸屬部門  官職隸屬類型

## 四、对项目的建议

### 4.1 「精确到月」的实现路径

**不做**：把 CBDB 的月份当数据源（1.2% 且是垃圾值）。

**要做**：
1. **月份作为"可选字段"**支持，不强制。我们的 schema 已有 `start_month`/`end_month`，
   正好承接；
2. **月度的可靠来源是中研院明實錄检索**，流程：
   - 用「人名 + 官职」检索 `check[]=3`
   - 解析返回的 時間/年號/出處/內容
   - 把命中的人工/半自动挂到对应 tenure 上，进 `discrepancy` 或直接补 `start_month`
3. **不臆造月份**：没查到就留 `NULL`，前端显示成只有年，不假装知道月份。

### 4.2 「扩展职官」的实现路径

**短期（本次 demo）**：仍用《明史》年表补官职，因为它的年份连续性好、可信度高。

**中期**：
- CBDB 快照提供 **34,271 个官职**与官职树（`OFFICE_TYPE_TREE`），
  可用于扩充 `office` 表与确立隶属关系；
- 但**必须过校勘**：CBDB 收了袁崇焕这类加衔者，与我们的口径冲突，
  且其年份范围常是一整段而非精确任免。

### 4.3 许可提醒（承接 DECISIONS D11）

CBDB 数据为 **CC BY-NC-SA 4.0**（含 ShareAlike）。引入后：
- 我们的**数据**仍可声明 CC BY-NC-SA 4.0（一致，无冲突）；
- 但**必须署名**，且**不得商业化** —— 与项目定位一致。

## 五、本次实测的可复现步骤

```powershell
# 1. 取最新快照元数据
curl -sL -x http://127.0.0.1:7897 https://raw.githubusercontent.com/cbdb-project/cbdb_sqlite/HEAD/latest.json

# 2. 下载（139 MB）并解压
curl -sL -x http://127.0.0.1:7897 -o cbdb.zip <huggingface_url>
Expand-Archive cbdb.zip -DestinationPath .

# 3. 校验（注意：校验解压后的 .sqlite3）
Get-FileHash cbdb_20261010.sqlite3 -Algorithm SHA256

# 4. 查月份填充率
python _verify\check_cbdb_db.py
python _verify\check_cbdb_chongzhen.py

# 5. 中研院月度检索
python _verify\check_month_precision.py
```

脚本位于 `_verify/`，可直接重跑。
