# MingOff 正式站（site/）

Next.js 15 静态导出站。**2026-10-17 按老板验收的 `web/demo.template.html`
逐项重做**（见 `docs/DECISIONS.md` D24）：外观与交互以 demo 为唯一真源，
不再"照着 demo 重新设计"。

## 快速上手

```powershell
# 1. 数据更新（仓库根 mingoff/）
$env:PYTHONPATH="src"; python -m mingoff.official
#   → src/mingoff/data/official_cabinet.json（v2：tenures + shilu）

# 2. 同步到站点
Copy-Item src/mingoff/data/official_cabinet.json site/src/data/cabinet.json

# 3. 构建（site/）
pnpm install
pnpm build        # 产物在 out/，静态文件可直接部署
```

本地预览：`npx serve out -l 3456`（静态导出不能用 `next start`）。

## 数据（v2）

`src/data/cabinet.json` = `official.py` 导出物，仅增加**展示字段**，未改任职段：

- `tenures[]`：张德信《明代职官年表》册1「內閣」360 段（1402–1644），
  新增 `tenure_type`（一律实授，不臆造署理/加衔）、`leave`（离任原因，注文动词直译）；
- `shilu{}`：中研院《明實錄》检索命中，按"命中公元年 ∈ 本人任期 ±1 年"筛选，
  每人最多 8 条 + `count`；抽屉里显示出处与原文，其余"另有 N 条，略"；
- 月份纪律不变：未载月份 = `null`，条上以左端虚线开口表示「起月未载」，不推断。

## 纪律

- `NULL ≠ 0`：月份未载显示为空/整年，不臆造（D4）
- 断限 1644.3：截断产物与史料原记月份分开陈述（D17）
- 实录原文不批量入自建库，只在抽屉展示与任期相关的命中并给出处（D10）
- 数据许可 CC BY-NC-SA 4.0，代码 Apache-2.0（D11）
- 字体用系统回退栈，不依赖 Google Fonts（境内/离线可用）

## ⚠️ 已知限制：数据源提取有缺行（未在本次修复）

本次只重做 UI；`tenures` 仍沿用上一轮从张德信年表 OCR 提取的 360 段。
**该提取层有已知缺陷**（实测）：

- 年表其实**逐年列名**（已回原书 PDF 核对：正統元年四人、正統二年三人、崇禎元年八人，
  长任期也不省略中间；见 `docs/evidence/`），但提取脚本丢弃了"无注文的人名行"，
  导致 1437 年等年份 0 条记录、正統元年缺張瑛；
- 另有少量 OCR/版式损失（如 1515 整块缺失、1554 年号头拆分）；
- 因此全朝视图会出现空档与不自然的断段（例：永樂元年视图全为淡化条）。

**三方互证中间没有断**：原书逐年名单 + 《明史》卷109（楊士奇 1402–1444 共 43 年
0 缺口）+ CBDB 跨年任命记录（楊榮 謹身殿大學士 1424–1440、張瑛 華蓋殿大學士
1426–1436 等）。详见 `docs/正式数据管线报告.md` 第七节。

**结论**：不需要换数据源，重写解析器（保留无注文人名行、展开合并单元格、年号头容错）
即可修好；是否重跑待老板拍板。当前站点数据保持现状，空档按源显示。
